# 🎯 AegisPay-AI: Razorpay Technical Interview & Architecture Defense

Use this document to prepare for the deep-dive technical interview round with Razorpay Senior Staff Engineers and Architects.

---

### Q1: "Walk me through the lifecycle of a transaction through AegisPay-AI."
* **Answer:**
  1. **Agent Tool Interception:** The AI agent formulates a structured `PaymentRequest(agent_id, user_id, amount, recipient_id, user_prompt, reason)`.
  2. **Stage 1 (Authorization):** AegisPay-AI verifies if the agent's ID is authorized to call the requested tool (`create_payment`).
  3. **Stage 2 (Policy Engine):** Evaluates spending limits, blacklist databases, and warning thresholds (`< 0.1ms`).
  4. **Stage 3 (Threat Detection):** Scans for prompt injections, calculates Shannon entropy for obfuscated payloads, and checks for intent divergence between the user's prompt and agent amount.
  5. **Stage 4 (Composite Risk Matrix):** Produces a weighted risk score (0–100) and outputs `ALLOW`, `REVIEW`, or `BLOCK`.
  6. **Stage 5 (Cryptographic Proof-of-Intent):** On `ALLOW`, generates an HMAC-SHA256 token binding payload parameters. The payment tool validates this signature before capturing the Razorpay order.
  7. **Stage 6 (Audit & Forensics):** Generates an immutable SHA-256 signed audit record and automated RBI-AML SAR packet.

### Q2: "Why didn't you use heavy RAG or LLMs in the synchronous critical path?"
* **Answer:**
  > *"RAG pipelines and vector database retrievals introduce 300ms–1500ms of latency, which violates payment gateway SLAs (< 50ms) and destroys checkout conversion. We designed a **pure in-flight deterministic security mesh**:*
  > * *The synchronous path (< 0.1ms) uses compiled regex automata, Shannon entropy math, and deterministic policy algorithms.*
  > * *Out-of-band background workers handle asynchronous regulatory forensics and deep compliance report generation without adding a single millisecond to the live payment SLA."*

---

### Q3: "What is Proof-of-Intent (PoI) and how does it prevent Man-in-the-Middle (MITM) attacks?"
* **Answer:**
  > *"Proof-of-Intent is a cryptographic commitment generated by AegisPay-AI upon verifying that an agent's request is benign. It signs the tuple `{request_id, agent_id, user_id, recipient_id, amount}` using HMAC-SHA256 with a server-side secret key.*
  > *When Razorpay's order creation client is called, it recalculates and validates that the requested payment amount exactly matches the signed commitment. Even if an attacker modifies the amount in transit by 1 paisa, the signature check fails and execution is aborted."*

---

### Q4: "How do you handle False Positives without hurting merchant checkout conversion?"
* **Answer:**
  > *"Rather than a binary ALLOW / BLOCK system, we engineered a three-tier decision matrix with a **`REVIEW` band (Risk Score 30–74)**. When a transaction violates a soft threshold (like an unusually high amount), AegisPay-AI triggers an adaptive Step-Up challenge (OTP / Biometric 2FA) rather than an outright block, preserving merchant conversion while maintaining security."*

---

### Q5: "How does AegisPay-AI integrate with Razorpay's existing architecture?"
* **Answer:**
  > *"AegisPay-AI operates as an API Gateway / Sidecar proxy directly upstream from Razorpay Order APIs. It integrates seamlessly with **Razorpay Thirdwatch** as the AI-native risk classifier, and with **RazorpayX** for corporate AI spending governance."*
